- (decision) Create a Pebble watch app that reminds users to sit for 45 minutes, stand for 10 minutes, and walk or move for 5 minutes; users may skip or extend phases.
- (decision) Project stakes: personal tool for the user's own use; use fast-path discovery and mark any inferred brief details as assumptions.
- (decision) Target broad Pebble support with watch-first operation and no phone dependency during use; skip advances immediately to the next phase, and extend lets the user choose added time.
- (assumption) Fast-path assumptions from selected options: sessions start and stop manually; pause/resume is available; reminders use vibration; stopping manually is sufficient outside desired hours. Success is a simple reliable reminder tool, with tracking and richer customization deferred. Exact Pebble platform compatibility and background execution must be validated during PRD/technical planning.
- (event) Drafted brief.md for review; captured project purpose, first-version scope, chosen phase behavior, inferred session/notification behavior as assumptions, and Pebble background/platform questions as open items.
- (event) Brief draft polished and audit complete: initial 45/10/5 sit-stand-walk idea, personal scope, watch-first/no-phone goal, skip-to-next, and user-chosen extension are captured; manual sessions, pause/resume, vibration, and no overnight schedule are marked assumptions; Pebble compatibility, extension increments, and customization remain open for PRD. Ready for user review.
- (decision) User specified Pebble Time 2 as the target model; updated the brief. Firmware/OS version and background behavior remain open pending verification.
- (decision) Architecture will verify Pebble Time 2 firmware/OS support for background timing and notifications before implementation; retained as an explicit downstream acceptance criterion.
- (decision) If the watch is powered off across phase deadlines, the app processes elapsed phases in order and issues only one notification for the resulting current phase; it does not replay stale reminders.
- (change) Architecture refinement: when phase deadlines are missed during device power-off, process elapsed phases in order, restart the resulting current phase at its full default duration from recovery time, and issue one haptic for the current phase only. User requires a phase Wakeup to vibrate and open the app to show phase and remaining time; operation after explicitly terminating the app is not required. Target-device behavior remains to be verified.
- (change) Architecture finalized additional behavior: +5/+10 minute extensions, UTC remains authoritative under device-clock adjustment, haptic-only signal with app foreground UI required at Wakeup, current phase is rebased to full duration on recovery for any expired deadline.
- (change) User confirmed Extend is silent; its later automatic phase transition still emits haptic. Removed stale invalid-clock wording; startup with invalid UTC leaves session inactive and shows an error.
- (change) Explicitly recorded that Extend is silent; Skip alone among manual controls produces one haptic.
- (decision) User may manually start the cycle at any wall-clock time; first Sit phase starts immediately and cycle timing is relative to start, not aligned to full hours.
- (decision) Add timed pause choices 5, 10, or 30 minutes. During timed pause, current phase is suspended with remaining time preserved; pause end resumes the same phase, opens/foregrounds app, shows that phase and remaining time, and emits one haptic without advancing the phase.
- (change) Clarified manual pause/resume separately from timed pause; brief states early Resume cancels timed Wakeup and stale callback does not reopen or request haptic.
